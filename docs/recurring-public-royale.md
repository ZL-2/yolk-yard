# Quality Update 137 — Public Player Hosts

Version 5.0.0 / protocol 43. The public FRONTIER match uses the first joining browser as its host. Render runs discovery, Social, reservations, progression storage and transport, with zero public simulations. Empty matches create no bot world or navigation on the relay.

The coordinator reserves the first host atomically. Other parties arriving during loading wait for that host's ready signal. The public roster remains 48 Intermediate contestants, with humans replacing bots, and sixteen spectator connections. Spawn Island lasts 30 seconds after the first human is ready. The battle map accepts landing markers before departure. Actual host simulation admission checks the cutoff again; late arrivals spectate and enter the next round when a seat is available.

Short transport interruptions resume the existing authenticated socket within its reconnect grace. Permanent host loss closes the host channels and elects the earliest surviving eligible member. Players restore their recovery checkpoint, including world ownership and the results restart deadline. New host address registrations require the elected member's live relay-session proof. The relay rejects an unrelated browser claiming FRONTIER. A host that stops advancing for 15 seconds loses its lease, including browsers that still respond to native pings. Deliberate friend spectators are excluded from election; public spectators can host the next round. There is no host transfer to a server simulation.

The public card publishes counts and the stage from a small host manifest. Readiness, reservations and host leases are coordinator-owned; the host owns gameplay decisions. Stage changes publish immediately. Public configuration, manual starts, private visibility and host kicks are disabled. New arrivals use the same fixed room address after migration. When no connected players remain, the room returns to first-player hosting.

Authenticated elected-host reports preserve public participation rewards through the existing bounded progression service, without moving bot or projectile simulation back to the relay. These reports follow browser-host authority and do not constitute server verification of each shot. Private matches retain their prior reward rules. Crown records are carried by admission and checkpoints and saved for their own connected contestant; spectating preserves saved ownership. Disconnecting from an active round relinquishes a carried crown, while results and warmup exits preserve it.

Essential checks cover concurrent first joins, 48 human replacements, the full 30-second window, late spectators, brief resume, voluntary departure, permanent loss, frozen host leases, world checkpoint recovery, joining after transfer, public results restart, airborne Shadowstep fall protection, doors, map planning, visual teammate footsteps, and browser scoreboard scrolling.

## Main-match leaderboards

The lobby shows the top 25 public Royale operators under Kills and Wins, plus the viewer’s personal rank. Admitted game sessions bind their progression account to the authenticated social member’s display identity. Kills are counted from accepted elimination events during combat; a main-match win counts once at round settlement. Private games, arena results, training, and bots cannot appear in the rankings. Totals persist alongside the existing progression file and survive receipt trimming; the available retained public receipt history is migrated once. Lobby requests are rate limited, rankings are cached, and no rank polling runs during matches.
