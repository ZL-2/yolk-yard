# Update 191 — voice channels and victory celebrations

Version 6.8.0, game protocol 69. Existing gameplay packets remain compatible.

Box Fights and Zone Wars prefer the human killer as the spectator target, including when a teammate is still alive. If that player is unavailable, a living eligible player is selected. Round and series winners can start, cancel and finish emotes during the result state; spectators receive the same emote and keep a camera on the winner. Extracted operators and winning Royale teammates also have celebration access. Result presentation does not revive a player in the simulation. Crouching removes any lingering footstep indicator and does not generate new footsteps.

Voice is explicitly enabled by the player and starts in listen-only mode. Microphone permission is requested separately. Default push-to-talk is Backquote; open microphone, input sensitivity, device selection, global and per-player volume, mute, deafen, friends/teammates privacy, preferred channel and speaking indicators are available in the sidebar. Key selection rejects conflicts with current gameplay controls.

Party voice works in the lobby and across game modes. Assigned-team voice uses the current match team or Zombies squad. Game voice is available only in Box Fights, Zone Wars and Free For All. Private code joins and public host aliases prove their game connection through the authenticated Social session. The server validates roster membership, room, team, blocks and channel on forwarding. Leaving a match removes its voice access; the preferred available channel or Party is restored. One active voice session per identity prevents duplicate microphones across tabs.

Audio uses a separate authenticated WebSocket, WebCodecs Opus when all listeners support it, and PCM compatibility audio otherwise. AudioWorklet handles capture and a bounded playback buffer outside rendering. Microphone capture stops when muted or push-to-talk is released. Channel changes reset queued audio. Reconnection rejoins without replaying old audio. Voice is live only: no recording or retained audio; reports send player identity, channel and written notes to the existing support inbox. Browser microphone/output permissions and device support still apply.

Performance work reuses immutable building/destruction snapshots until their revision changes, limits construction ticks to unfinished or repairing structures, caches HUD markup, and groups voice recipients by channel instead of scanning every connected user for each packet. In the local identical workload with 16 players, 1,500 structures and 400 damaged objects, snapshot creation fell approximately 80–92% and completed-construction checks over 99%. These are CPU-work measurements, not a hardware-independent FPS promise.

Focused validation includes real microphone-tone capture and audible playback between two desktop browsers; push-to-talk, open mic, mute/deafen, channel changes, compatibility audio and reconnect; authenticated public/private/team membership; winner emote replication and round reset; actual lobby/sidebar and winner screen rendering; crouch-indicator removal; snapshot isolation and build repair/edit regressions. Mobile checks are outside this release scope.

References used for behavior: Epic Games, “How do I manage my party, voice chat, and text chat options from the Fortnite Lobby?” and Fortnite Creative “Mode Settings”; W3C WebCodecs Opus registration. This implements the documented channel and control behavior within Ravelfront, using its own UI and transport rather than Fortnite's private services.
