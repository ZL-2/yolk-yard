# Quality Update 167 — Stay in the Fight

Production logs on October 16 show public hosts removed for `Public host stopped advancing`, including single-member rooms at 18:29:12, 18:51:10 and 18:58:11 UTC. The relay evicted any host whose published simulation clock did not advance for 15 seconds, even if its native WebSocket connection remained alive and no guest could restore the round. Rendering follows requestAnimationFrame, which can stop when a browser suspends a tab. A solo match then had no surviving copy accessible through the relay. These logs confirm the eviction defect, but do not establish which event was the reported friend's match or why that browser stopped advancing.

The existing eight-second client reconnect deadline and ten-second server retention also made a temporary outage fatal. Recovery now retries for 30 seconds and retains the authenticated session for 35 seconds. Stalled-host transfer waits for transport recovery and requires a fresh same-round successor. Live solo hosts retain their lease through rendering stalls; matchmaking avoids stalled rooms. Startup leases without any initialized state still expire, and genuinely disconnected sessions still expire after their recovery grace.

No cross-room reset was reproduced. Real-socket regression starts and closes another public room while an existing solo match has two survivors, then resumes that original match with the same identity and inventory. The old implementation fails this test and both lease eligibility regressions. Production error-level logs were empty for the reviewed interval; sampled memory remained below 136 MB and CPU below 0.11 CPU during 18:00–19:15 UTC. Separate `Server stopping` entries at 19:12:28 correspond to the previously authorized deployment, which interrupted two active rooms.

Focused validation covers final-two preservation, stale/old-round successor rejection, live host transfer, recovery beyond eight seconds, multi-room isolation, six-player checkpoint congestion, party admission and ordered transport replay. Existing real host handoff checks pass. Desktop browser and deployed-version checks run in CI; mobile and unrelated suites are excluded. Protocol 58 remains compatible. Persistent internet loss, closing the sole host browser and server deployment restarts still cannot preserve a player-hosted world indefinitely.
